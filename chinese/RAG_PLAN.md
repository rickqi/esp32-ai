> 日期: 2026-08-01 | 基于: PLAN_AB_RETRAIN_RAG.md 方案 B
> 目标: 解决 12.5-13.7M 小模型"能生成医学文本但答不准"的根本缺陷

---

## 一、现状与差距

| 项 | 现状 |
|---|---|
| 模型 | zh5-multi2（13.7M），val ppl 7.0 |
| 生成能力 | ✅ 真实医学内容（肺癌症状/药物/结构化列举） |
| 精准问答 | ❌ 无法从问题检索到精确答案（架构上限） |

## 二、三种 RAG 架构对比

### B1: 设备端全 RAG（ESP32 检索 + 生成）

```
串口问题 → ESP32 TF-IDF检索(PSRAM索引) → 检索段落 → 拼prompt → 模型生成
```

| 维度 | 评估 |
|---|---|
| 离线 | ✅ 完全离线 |
| 索引 | 1-2MB 倒排索引（PSRAM 余量 4.3MB） |
| 中文检索 | 字符级（与 tokenizer 一致，简单可靠） |
| 检索质量 | 关键词匹配（无语义） |
| 小模型利用 | ⚠️ 256 token 上下文，片段必须 ≤100 字符 |
| 风险 | 需要 RAFT 微调让模型"抄写"检索内容才能有效 |

### B2: PC/上位机 RAG（doc-search + DeepSeek）

```
PC 问题 → doc-search BM25 → 相关段落 → DeepSeek 生成精准回答
```

| 维度 | 评估 |
|---|---|
| 质量 | ✅ 最高（BM25 + 大模型） |
| 复用 | ✅ doc-search 现成（Tantivy 索引已构建） |
| 缺点 | ❌ 非设备端，需 PC 连接 |
| 适用 | 演示/验证 / 上位机场景 |

### B3: 混合（PC 构建索引 → 设备端检索）★推荐

```
PC: 知识库 → 压缩倒排索引（1-2MB）→ 烧录设备
设备: 问题 → TF-IDF检索 → 片段 → 模型续写
```

| 维度 | 评估 |
|---|---|
| 离线 | ✅ 设备可用 |
| 索引构建 | PC 端一次性（Python 脚本） |
| 检索实现 | ESP32 C 代码（倒排 + 打分，~500 行） |
| 可控 | ✅ 片段长度/数量可调（适配 256 token） |
| 风险 | 关键词匹配误检；小模型对检索上下文利用有限 |

**推荐 B3**：平衡离线可用 + 实施可控。

## 四、设备端检索实现（ESP32）

### 4.1 索引格式（1-2MB）

```
倒排索引（PSRAM）:
  词表: 字符级（复用 6594 词表，无需新 tokenizer）
  格式: char_id → 文档列表（doc_id + tf 权重）
  文档: 知识库条目（question+answer 片段，~100 字符/条）
  压缩: uint16 存储, 二值化 IDF, 只保留 top 字符
```

### 4.2 检索算法

```
1. 问题分词（字符级，与模型 tokenizer 一致）
2. 查倒排索引 → 候选文档（AND/OR 匹配）
3. TF-IDF 打分（ESP32 可计算）
4. 取 top-2/3 片段
5. 组装 prompt:
   [知识片段1] [知识片段2] [问题] 请据此回答
```

### 4.3 PSRAM 预算

| 项 | 大小 |
|---|---|
| 模型（已用） | 3.73MB |
| 倒排索引（新） | 1-2MB |
| 剩余 | ~2-4MB 余量 ✅ |

## 五、RAFT 微调（关键增强）

小模型对检索上下文利用差（研究: 360M 模型 RAG 0% 准确率）——需微调教模型"抄写"检索内容：

```
训练样本: [知识片段] [问题] → 模型应复述片段中相关内容
方法: 用 DeepSeek 生成"检索+回答"训练对（已验证 DeepSeek 精准）
数据: 1-2K 条（从 Huatuo26M-Lite 采样）
```

## 七、风险与边界

| 风险 | 缓解 |
|---|---|
| 关键词检索误检（无语义） | 字符级 TF-IDF + top-K 多候选；问题相似度过滤 |
| 小模型上下文利用差 | RAFT 微调（教模型抄写检索内容） |
| PSRAM 竞争 | 索引压缩到 1-2MB；必要时降低知识库规模 |
| 中文分词边界 | 字符级（与模型一致，无分词歧义） |
| 索引构建与烧录 | PC 脚本生成 .bin，esptool 烧录到数据分区 |

---

## 八、验收标准

```
1. 知识库索引 ≤ 2MB，烧录成功
2. 设备端检索 ≤ 50ms（ESP32）
3. 实测: "甲状腺切除是否会造成晕倒" → 检索到相关片段 → 生成有依据回答
4. 8 标准问题 ≥ 6/8 命中知识库且回答引用检索内容
5. 推理速度 ≤ 2.5 tok/s（现有 + 检索开销）
```
