## 二、优化方向（按优先级）

### P0: 混合量化（收益最大,消除生成噪音）

**现状**: 4-bit group=32 是妥协方案(README 记录: group=128 崩溃 ">>>>>"、group=32 可用但质量受损)。

**方案**: **8-bit core(前几层或 dense 核心) + 4-bit PLE table**
- README 已记录此方向("8-bit core + 4-bit table ~9MB")
- PLE 表(tok_emb + ple_table)占参数量大头,对量化敏感度低 → 可保持 4-bit
- dense 核心(qkv/proj/gate/up/down)是生成质量关键 → 升 8-bit 降噪
- 预期: model.bin 增至 ~9.5-10MB,**需扩 model 分区**(当前 0x890000 仅余 0.06MB)

**前置**: 分区表扩展 —— model 分区 0x890000 → 需 ≥ 10MB。
建议: 压缩 kb 索引(1.83MB→~1MB)或调整 factory/model/kb 边界,腾出空间。

### P1: 采样参数微调（✅ 已完成,2026-08-02 落地）

**现状（原）**: `SAMPLING_TEMP=0.7, TOPK=40, REPETITION_PENALTY=1.4`
实测"NSV-80岁多发展成活跃"等噪音开头 → 建议:
- **REPETITION_PENALTY 1.4 → 1.5-1.6**(更强抑制重复/噪音)
- **SAMPLING_TEMP 0.7 → 0.6**(更保守,减少随机乱码)
- 可加 **开头的 top-k 收紧**:前 5-10 token 用 TOPK=10,之后放宽到 40

**已执行**: `TEMP=0.6, TOPK=40, REPETITION_PENALTY=1.5`(提交 `891d192`)
设备实测噪音开头消失,连贯度提升,3.11 tok/s 性能不变。见顶部"进度总览"。

### P2: RAG 检索增强（检索已优,锦上添花）

**现状**: 检索质量已验证优秀(Top-5 全相关),但模型复述保真度有限。

**方案**:
- **Top-1 注入优先**: 当前注入 Top-2 可能稀释;实测 Top-1 往往已含完整答案,
  可测 Top-1 vs Top-2 效果对比
- **索引扩量**: 10000 docs → 50-100K(Huatuo26M-Lite 全量),
  但需评估 kb 分区容量(当前 2MB 放 1.83MB 已满)
- **多轮检索**: 问题 → 初检 → 扩展问题 → 精检(中成本)

### P3: 生成质量(RAFT 微调改进)

**现状**: RAFT 让模型"复述证据",但复述保真度有限(把证据写乱)。

**方案**:
- **证据前缀引导**: 训练时加 `[证据]` 标记,让模型明确"这是要复述的内容"
- **RAFT 数据增强**: 提高证据→回答的对齐度,训练"忠实复述"而非"自由发挥"
- **指令格式统一**: SFT 固定模板,避免生成时格式漂移

### P4: 系统层面(结构性)

- **分区扩展**: model 0x890000(8.98MB)余量 0.06MB 太紧,v3 需更大分区
  (压缩 kb 索引或重排 factory/model/kb 边界)
- **速度优化**: FFN=374 比 v2 的 244 大 53%,是推理变慢主因
  —— 评估降 F 或蒸馏更小核心(24M→20M)
- **显示优化**: 14px CJK 在 400x300 屏偏小,可评估 16px(需重新生成字库)
- **多语言**: v3 已验证 RAG 链路,可移植到英文固件(esp32_llm 无 RAG)

## 三、优先级与预期收益

| 优先级 | 优化项 | 成本 | 预期收益 |
|---|---|---|---|
| **P0** | 混合量化(8bit core + 4bit table) | 中(重导出+扩分区) | **消除生成噪音,质量质变** |
| **P1** | 采样参数调优 | 零(改常量+重编译) | 立即改善,抑制乱码开头 |
| **P2** | RAG Top-1 + 索引扩量 | 低-中 | 回答更聚焦,覆盖面更广 |
| **P3** | RAFT 数据增强 | 中(重训练) | 复述保真度提升 |
| **P4** | 分区/速度/显示 | 高 | 结构性改进 |

**建议执行顺序**: P1(立即) → P0(核心) → P2/P3(并行) → P4(按需)
